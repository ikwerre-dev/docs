The Node SDK uses the same domain workflow as the Pxxl dashboard. Use it from a trusted backend, CI job, or internal tool with an API key that has `scope=domain`, `scope=domains`, or `scope=all`.

```bash
npm install @pxxlapp/pxxl
```

```ts
import { PxxlClient } from '@pxxlapp/pxxl';

const pxxl = new PxxlClient({ apiKey: process.env.PXXL_API_KEY! });
```

## Connect a Domain

```ts
const connected = await pxxl.connectDomain({
  domain: 'example.com',
  projectId: 'proj_123',
});

console.log(connected);
```

The response includes the domain ID, status, management mode, expected `A` record target, route status, and whether a deployment refresh is pending.

After connection, Pxxl registers the proxy route immediately when the project has an active deployment. DNS activation has two paths:

- `verifyDomainRecord` checks the expected `A` record right now and is the best choice after you update DNS.
- Pxxl also auto-detects pending external domains for up to 24 hours after connection. The backend checks every 5 minutes and activates the domain once the expected record resolves.

## Connect to a Microservice

For monorepo or multi-service projects, pass the microservice ID as `microserviceId`, `serviceId`, or `serviceAlias`:

```ts
const connected = await pxxl.connectDomain({
  domain: 'api.example.com',
  projectId: 'proj_123',
  microserviceId: 'api',
});
```

Pxxl keeps the domain attached to the parent project and routes traffic to the selected microservice target.

## Bulk Connect

`connectDomains` processes domains one by one. Valid domains are accepted and plan-limit failures are returned in `rejected`, so you can show partial success instead of losing the whole batch.

```ts
const result = await pxxl.connectDomains([
  { domain: 'app.example.com', projectId: 'proj_123' },
  { domain: 'api.example.com', projectId: 'proj_123', serviceAlias: 'api' },
]);

console.log(result.accepted);
console.log(result.rejected);
```

When a plan limit is exceeded, rejected items include the HTTP status, message, limit, used count, and backend details.

## Verify Records and Activation

```ts
await pxxl.verifyDomainRecord({
  domain: 'example.com',
  projectId: 'proj_123',
});

await pxxl.activateDomain('dom_123');
await pxxl.getDomainConnectionStatus('dom_123');
```

Use `verifyDomainRecord` after adding the expected DNS records. It works for normal external domains and Pxxl-managed domains.

Use `activateDomain` or `getDomainConnectionStatus` to check activation, proxy routing, and SSL readiness. `getDomainConnectionStatus` follows the same dynamic flow as the dashboard: it uses `.cv` managed zone status for `.cv` domains, and the generic activation check for every other TLD.

`getDomainZoneStatus` is still available for older code, but it now delegates to `getDomainConnectionStatus` so non-`.cv` domains do not fail with a `.cv`-only zone-status error.

## Resync the Proxy Route

Use `resyncDomainProxy` after changing the connected project, microservice target, SSL settings, force-HTTPS setting, or DNS state. It asks Pxxl to refresh the route and certificate state without rebuilding the project.

```ts
const resync = await pxxl.resyncDomainProxy('example.com');

console.log(resync);
```

For team-scoped domains, pass `teamId`:

```ts
await pxxl.resyncDomainProxy('example.com', {
  teamId: 'team_123',
});
```

The method uses `POST /api/v3/cli/domains/:domain/resync`. It requires an API key with domain scope and `read_write` permission.

## DNS Records

Pxxl-managed domains can be edited through the SDK.

```ts
await pxxl.listDomainDNSRecords('dom_123');

await pxxl.createDomainDNSRecord('dom_123', {
  type: 'A',
  name: '@',
  value: '193.181.212.65',
  ttl: 60,
});

await pxxl.updateDomainDNSRecords('dom_123', {
  recordId: 'rec_123',
  type: 'A',
  name: '@',
  value: '193.181.212.66',
});

await pxxl.deleteDomainDNSRecord('dom_123', {
  recordId: 'rec_123',
});
```

Pxxl blocks invalid `CNAME` and `A` record conflicts before saving.

## Disconnect a Domain

Use `disconnectDomain` when a custom domain should stop routing to a project. This removes the project binding and proxy route, but it does not delete the domain from your registrar.

```ts
await pxxl.disconnectDomain('example.com', {
  projectId: 'proj_123',
});
```

Pass `teamId` when disconnecting a domain inside a spaceship:

```ts
await pxxl.disconnectDomain('example.com', {
  projectId: 'proj_123',
  teamId: 'team_123',
});
```

| Option | Required | Description |
| --- | --- | --- |
| `domain` | Yes | Hostname to disconnect, such as `example.com` or `api.example.com`. |
| `projectId` | Recommended | Project currently connected to the domain. Include it to avoid removing the wrong binding. |
| `teamId` | No | Spaceship context for team-owned domains. |

## Nameservers and Pxxl DNS

```ts
await pxxl.verifyDomainNameservers('dom_123');
await pxxl.updateDomainNameservers('dom_123', ['ns1.example.com', 'ns2.example.com']);
await pxxl.switchDomainToPxxlDNS('dom_123');
```

For Pxxl-managed domains, you can also create managed subdomains:

```ts
await pxxl.createManagedSubdomain('dom_123', {
  label: 'api',
  projectId: 'proj_123',
});
```

## Certificates

```ts
const certificate = await pxxl.downloadDomainCertificate('dom_123');
```

The returned `Blob` contains the public proxy certificate PEM.

## Plan Limit Errors

If the account exceeds its custom-domain allowance, the API returns a structured error:

```json
{
  "code": "DOMAIN_LIMIT_EXCEEDED",
  "message": "Your current plan allows up to 1 custom domains. You already have 1. Upgrade your plan to add more domains.",
  "limit": 1,
  "used": 1,
  "accepted": 0,
  "rejected": ["example.com"]
}
```

Use `connectDomains` when submitting multiple domains so the SDK can keep accepted domains separate from rejected ones.
